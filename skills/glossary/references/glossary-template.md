# Glossary template

Keep the headings and the entry form exactly as written. Replace every
`<placeholder>`.

Rules for filling:
- Write one `##` section per subject, and entries in alphabetical order
  inside a section.
- Write one entry per term: `- **Term**: definition.`
- Write an entry only for a term that passes the entry test: two readings at
  one usage at least, no word with one reading that fits every usage, and no
  sentence that settles it.
- Start a definition with a noun phrase that names the kind of thing. Keep it
  to at most two sentences: what it is, then a boundary or an example.
- Write no path, placeholder, format, list of allowed values, section list,
  or condition in a definition.
- Write no entry for a term that no document in the set uses.

---

```markdown
# Glossary

Every word below has two readings in <the document set: the files, or the
rule that selects them> that no other word settles. Each entry gives the one
reading that holds. <One sentence on where restatements live, when a document
restates entries. Example: A skill's Terms section restates the entries it
uses with the same text.>

## <Subject>

- **<Term>**: <what it is, as a noun phrase. Example: a user assigned the
  patient role in the app.>
- **<Term>**: <what it is.> <Boundary or example. Example: Never a subagent.>
- <...>

## <Subject>

- <...>
```
